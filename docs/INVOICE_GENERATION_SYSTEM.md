# Invoice Generation System

## Overview

Invoices are PDF documents generated for completed orders and emailed to customers. They are **only generated after payment has been verified** — this is a critical security invariant enforced at every entry point.

## Security: Payment Verification Guard

**Invoices CANNOT be generated for unpaid orders.** This is enforced at 3 layers:

| Layer | File | Guard |
|-------|------|-------|
| Core function | `src/lib/invoice.ts` → `generateInvoice()` | Queries `upi_payments` for `status: 'VERIFIED'`; throws error if not found |
| API endpoint | `src/app/api/orders/[id]/invoice/route.ts` | Returns 403 before calling `generateInvoice()` if payment not verified |
| Status trigger | `src/app/api/orders/[id]/status/route.ts` | Async payment check before firing `sendInvoice()` in background |

**Payment statuses:**
- `PENDING` — payment submitted, awaiting admin verification → **NO invoice**
- `VERIFIED` — admin confirmed payment is valid → **Invoice allowed**
- `FAILED` — payment rejected → **NO invoice**

## Order & Invoice Lifecycle

```
Customer places order (PENDING)
    ↓
Customer submits UPI payment → upi_payments created (status: PENDING)
    ↓                          Order status → PAYMENT_RECEIVED
    ↓                          Stock atomically decremented
    ↓                          ❌ No invoice generated here
    ↓
Admin verifies payment → upi_payments.status → VERIFIED
    ↓
Admin changes order status → CONFIRMED / PROCESSING / SHIPPED / DELIVERED / COMPLETED
    ↓
    ├── ✅ Payment verified? → Generate invoice PDF → Email to customer
    └── ❌ Payment not verified? → Skip invoice, log warning
```

## Entry Points for Invoice Generation

### 1. Admin status change (primary trigger)

**Endpoint:** `PUT /api/orders/[id]/status`
**File:** `src/app/api/orders/[id]/status/route.ts`

When admin sets status to `CONFIRMED`, `DELIVERED`, or `COMPLETED`:
1. Checks `upi_payments.status === 'VERIFIED'` for the order
2. If verified → calls `sendInvoice()` (generates PDF + emails customer)
3. If not verified → logs warning, skips invoice

### 2. On-demand customer/admin request

**Endpoint:** `GET /api/orders/[id]/invoice`
**File:** `src/app/api/orders/[id]/invoice/route.ts`

- Returns existing invoice if already generated
- If no invoice exists, checks payment verification first
- Returns `403` with message "Payment must be verified first" if unverified
- Generates on-demand only if payment is verified

### 3. Core generation function

**Function:** `generateInvoice(orderId)`
**File:** `src/lib/invoice.ts`

- Fetches order + order items + product details
- **Checks `upi_payments.status === 'VERIFIED'`** — throws if not found
- Returns existing invoice if already generated (idempotent)
- Generates PDF via jsPDF → uploads to Vercel Blob → creates DB record

## Purchase Flows

### Normal cart checkout

```
Cart → /checkout (CheckoutWithOTP)
  → Send OTP → Verify OTP
  → POST /api/checkout/verify-and-place-order (creates order, status: PENDING)
  → UPIPaymentModal shown
  → POST /api/checkout/upi-payment (payment submitted, status: PAYMENT_RECEIVED)
  → Admin verifies → Invoice generated
```

### Chatbot checkout

```
Chat/Shop tab → Buy → Sign in (if needed) → ChatCheckout
  → Enter details + pincode → OTP verification
  → POST /api/checkout/verify-and-place-order (creates order, status: PENDING)
  → ChatPayment (UPI QR + transaction ID)
  → POST /api/checkout/upi-payment (payment submitted, status: PAYMENT_RECEIVED)
  → Admin verifies → Invoice generated
```

Both flows use the **same backend APIs** — no invoice is generated at any checkout step.

## Invoice PDF Contents

Generated by `generateInvoicePDF()` using jsPDF + jspdf-autotable:

- Company header (Kosvana / Mush Agro Products)
- Invoice number (format: `INV-YYYYMMDD-XXXXX`)
- Order number, date
- Customer billing & shipping addresses
- Items table: Product | Qty | Unit Price | Amount
- Totals breakdown:
  - Subtotal
  - Product Discount (if applicable, shown in green)
  - Convenience Fee
  - Shipping (or FREE)
  - Coupon Discount (if applicable, shown in green)
  - **Total**
- Footer with thank-you message

## Invoice Email

Sent via `sendOrderInvoiceEmail()` in `src/lib/email.ts`:

- Professional HTML template
- Order summary with items
- Price breakdown (same as PDF)
- Download link to PDF (Vercel Blob URL)
- Shipping address
- Contact information

## Database Schema

```prisma
model Invoice {
  id              String   @id @default(cuid())
  invoiceNumber   String   @unique
  status          InvoiceStatus @default(DRAFT)
  pdfPath         String?           // Vercel Blob URL
  orderId         String   @unique
  order           Order    @relation(...)
  customerName    String?
  customerEmail   String?
  subtotal        Float?
  tax             Float?
  shipping        Float?
  total           Float?
  invoiceItems    Json?
  emailSent       Boolean  @default(false)
  emailSentAt     DateTime?
  generatedAt     DateTime?
}

model upi_payments {
  id              String   @id
  orderId         String?
  amount          Float
  status          String   // PENDING | VERIFIED | FAILED
  transactionId   String   @unique
  resourceType    String   // 'order' or 'training_registration'
  verifiedByUserId String?
}
```

## Troubleshooting

### "Invoice cannot be generated: payment not verified"
This is the payment guard working correctly. The order's payment must be verified by an admin before an invoice can be generated. Check `upi_payments` table for the order's payment status.

### Invoice not generated after status change
Check the server logs for: `Skipping invoice for order ORD-XXX: payment not verified`. This means the order status was changed but payment hasn't been verified yet. Verify the payment first, then change the status again.

### Customer can't download invoice
The `GET /api/orders/[id]/invoice` endpoint returns 403 if payment isn't verified. The customer will see "Invoice is not available yet."
